New to AI agents? Read these ten terms first

Dara is already built and running. These are the words the reports use most. Underlined terms in the reports link back here.

Capability
One specific job the agent does, such as "flag a curriculum gap every morning" or "answer a student's DM". Dara has 38 candidate capabilities. Autonomy is approved per capability, never for the whole agent.
Autonomy ladder (R0–R9)
The platform's ten levels of how much an agent may do alone, from R0 "define the workflow" up to R9 "reliable operation and ownership". Each capability has a starting level and a ceiling it can never exceed.
Human-reserved
A decision a person must make at every level, forever, for example what students are taught. The code caps these at R5, so the agent can prepare and propose but never decide.
Approved autonomy
The level a human has actually signed off for a capability. Until one is recorded, the platform treats the capability as having no authority at all.
Tool call
The model asking the code to do something specific, such as escalate_to_human. Dara's model may make at most one tool call per reply, so it can't loop.
Shadow mode
A safety check that evaluates and logs what it would do but never blocks. It's useful for watching, but it doesn't protect anything. Dara's authorization gate defaults to shadow.
Fail-open
When a check breaks, it lets the action through instead of stopping it. Fail-closed is the opposite. Several of Dara's checks fail open.
Agent registry
The code file that lists every agent on the platform, with its schedule, tools and on/off flag: agentRegistrySeed.ts. It only sets starting values; production can differ.
Handoff
Passing a piece of work to someone else. Dara can hand off to a human (a ticket plus a Basecamp to-do). There is no way for her to hand off to another AI agent.
file:line citation
A pointer such as daraReplyService.ts:182, meaning that file at that line. Every claim in these reports carries one, or the word "unknown".
